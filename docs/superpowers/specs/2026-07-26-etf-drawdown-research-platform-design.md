# 指數 ETF 回撤加碼研究平台設計規格

日期：2026-07-26
狀態：已完成互動設計確認，待書面規格核對
產品暫名：**Drawdown Ledger／回撤帳本**

## 1. 產品目標

本產品是一套本機優先的指數與正向槓桿 ETF 研究平台。它回答的不是「明天會不會漲」，而是：

> 當原型指數或 ETF 自歷史高點回撤某個幅度時，過去出現過多少次獨立事件；若在下一個交易日買進，後續報酬、續跌、修復與資金耗盡風險如何；在每月持續累積現金且永不賣出的前提下，哪些分層加碼比例在不同歷史區間都相對穩健？

平台必須同時做到：

1. 以每個歷史交易日作為研究起點。
2. 將「每日條件樣本」與「獨立回撤事件」分開，避免把重疊日期誤稱為獨立機率。
3. 槓桿 ETF 同時呈現原型跌幅、槓桿 ETF 自身跌幅與兩者後續報酬。
4. 模擬每月可變投入、現金利息、股息去向、觸發式加碼、新高重置與永不賣出。
5. 以可解釋、可重現的窮舉與時間外驗證，提出積極、平衡、保守三組候選策略。
6. 在沒有 AI API 的情況下，仍可讓其他 AI 透過專屬頁面、固定欄位、JSON 與本機 API 操作。
7. 提供本機完整服務、Tailscale Funnel HTTPS、GitHub Pages 靜態備援，以及可復原的 GitHub 工程流程。

本產品提供歷史研究與決策紀律工具，不提供保證報酬、即時喊單或個人化投資建議。

## 2. 已確認的產品原則

- **訊號與報酬分離**：回撤觸發以不含股息的價格報酬序列判定；持有績效以總報酬與實際現金流計算。
- **收盤判定、次日成交**：交易日 `t` 收盤才知道觸發，最早於 `t+1` 開盤成交，杜絕同日收盤成交的前視偏誤。
- **只買不賣**：所有加碼部位永久保留；創新高只重置下一輪觸發旗標，不清倉。
- **現金持續累積**：未觸發的每月投入與現金利息保留在資金庫，下一輪仍可使用。
- **新高重置的是比例基準**：創新高後，當下全部可用現金視為新週期的 100%；系統不憑空補足現金。
- **真實與合成分離**：槓桿 ETF 上市前的合成壓力史不得與上市後實際績效混成同一個實績樣本。
- **穩定區域優先**：最佳策略不是歷史單一最高分，而是跨時間切片、鄰近參數與壓力情境都不易崩解的候選區域。
- **資料可追溯**：每份結果記錄資料來源、抓取時間、政策截止日、實際最後交易日、參數、引擎版本與資料雜湊。

## 4. 資料截止與更新政策

### 4.1 政策截止日

每次啟動都計算「上個曆月最後一天」：

- 8 月任一天啟動，政策截止日固定為 7 月 31 日。
- 若政策截止日不是交易日，實際最後觀測日為該日以前最近的有效交易日。
- 介面同時顯示「政策截止日」與「實際最後交易日」，不把兩者混為一談。

### 4.2 穩步更新

1. 啟動時先讀本機資料清單，不直接抓網路。
2. 若所有必需序列已覆蓋所需交易日，完全不發出 Yahoo 請求。
3. 若落後，只抓缺少區間並向前重疊 5 個交易日，用於辨識供應端對拆分、股息或近期價格的修訂。
4. 更新採每個代碼獨立鎖、指數退避與節流；失敗不破壞上一版有效快取。
5. 新資料通過欄位、單調日期、重複列、OHLC 關係、非正價格、極端跳動與公司行動檢查後，才以原子替換寫入。
6. 極端行情只標記人工檢視，不以固定漲跌幅門檻自動改寫真實價格。

### 4.3 資料層次

- 市場資料：依代碼與頻率儲存為 Parquet。
- 資料清單：SQLite 記錄覆蓋範圍、來源、更新時間、雜湊、品質狀態。
- 使用者策略、回測結果、工作佇列：SQLite。
- 明確匯出的匿名報告：靜態 JSON／HTML，可選擇發布至 Pages。
- Yahoo 快取、私人策略與回測結果全部列入 `.gitignore`。

Yahoo 資料只作個人研究用途；資料層以 provider 介面隔離，未來可替換成付費或官方來源。

## 5. 價格、總報酬與公司行動語義

每個交易日保留：

- `open/high/low/close`：拆分調整、但不含股息的價格序列，用於回撤、成交與部位估值。
- `adj_close`：含股息效果的調整收盤，用於純持有總報酬統計與交叉驗證。
- `dividend`：每股現金股息事件。
- `split_ratio`：拆分事件。

核心規則：

1. 回撤只使用價格 `close`：

   `drawdown[t] = close[t] / max(close[0:t]) - 1`

2. 事件後固定期報酬使用總報酬指數，並以次日開盤作為可交易起點。
3. 策略模擬用實際股數、現金股息、拆分與價格估值，不再額外套用 `adj_close`，避免股息重複計算。
4. Yahoo 只有除息日而沒有可靠付款日時，研究模型在除息事件後下一個交易日開盤處理股息，報告必須標示此近似。
5. 原始供應資料、正規化後資料、衍生指標分層保存；衍生值不得覆寫來源列。

## 7. 歷史證據分析

### 7.1 每日條件樣本

對每個門檻 `d`，所有 `drawdown[t] <= -d` 的交易日都是一個可查詢起點：

- 訊號日：`t` 收盤。
- 假設成交：下一個有效交易日開盤。
- 報告 1、3、6 個月與 1、3、5 年的總報酬分布。
- 同時報告樣本數 `N_day`、日期覆蓋與重疊警告。
- 此資料可回答「歷史上任一天看到這種跌幅，後來怎樣」，但不得宣稱每一天互相獨立。

信賴區間使用時間序列區塊重抽樣，而非把每一天當獨立伯努利樣本。

### 7.2 獨立回撤事件

一個週期從創新高開始，到下一次創新高結束。對每個門檻：

- 每個週期只記第一次收盤跌破該門檻。
- 若單日跳空跨越多層，該週期可同日觸發多個不同門檻，但每層仍只計一次。
- 每層回報獨立事件數 `N_episode`。
- 策略結論與主要證據句優先使用獨立事件。

### 7.3 每個起始日

使用者可選任意曆日。系統映射到該日或之後第一個有效交易日，並使用當時以前的真實歷史高點計算初始回撤，不把研究起點價格誤當新高。

若起始日已在回撤中：

- 起始日收盤後，所有尚未觸發且當下已滿足的門檻一次成立。
- 於下一個交易日開盤，依淺至深順序執行。
- 這讓「在歷史上每一天打開程式並開始執行」成為可重現情境。

### 7.4 指標

每個門檻至少顯示：

- `N_day`、`N_episode` 與資料期間。
- 固定期報酬的平均、中位數、四分位、正報酬率與 5%／95% 區間。
- 進場後最大不利變動（MAE）與最大有利變動（MFE）。
- 再跌 5、10、20 個百分點的機率。
- 5% 期望短缺（ES5%），不只顯示單一最差值。
- 回到買入價、回到前高的交易日分布與未修復比例。
- 最大套牢幅度、最長套牢時間與期末仍套牢比例。
- `V 型修復率`：觸發後 126 個交易日內回到觸發前高的獨立事件比例。

主要敘事格式：

> 原型首次跌破 -30% 時，歷史共有 N 次獨立回撤事件（另有 N_day 個重疊日樣本）。以下一交易日開盤買進計算，一年後總報酬中位數為 X%，正報酬率為 Y%；其中 Z% 在 126 個交易日內回到前高，最差 5% 情境平均仍再跌 A%，最長修復 B 個交易日。

句尾固定附資料截止、標的、實際／合成狀態與樣本不足警告。

## 8. 槓桿 ETF 分析

槓桿頁固定分三層，使用不同標籤與圖例：

1. 原型價格／指數及其回撤：預設加碼訊號。
2. 理論每日重置槓桿合成淨值：只作上市前壓力測試。
3. 實際槓桿 ETF 市價與總報酬：上市後可交易績效。

不可把縮放後的合成 NAV 顯示為真實 ETF 美元或台幣市價。真實與合成的交接點必須有垂直標記，所有統計分成：

- 實際 ETF 上市後。
- 原型可用的長期歷史。
- 合成壓力史。

合成模型採原型每日價格報酬、名目倍數、費用與可配置摩擦成本；報告明確聲明它不能完整重建期貨轉倉、融資、基差、稅務與實際追蹤誤差。任何使用整段真實資料校準的模型只能標記為「事後描述」，不得進入樣本外策略評分。

## 9. 現金庫加碼策略

### 9.1 參數

- 研究起始日與結束日。
- 初始持股、初始現金。
- 每月基本投入額。
- 年度成長率；每滿 12 個月在下一個投入月生效。
- 進階日期表：可設定永久調薪、暫停、恢復、單次獎金或單次額外投入。
- 每月投入日；預設每月 1 日，於當日或之後第一個交易日開盤前入帳。
- 現金年利率；按實際經過日數以 ACT/365 累積。
- 股息處理：留在現金庫或於事件後下一交易日開盤再投入。
- 交易費、稅與滑價；預設皆為 0，但報告保存假設。
- 回撤門檻與每層使用比例。

### 9.2 觸發與執行

1. 每日先處理日期已到的現金利息與投入。
2. 處理拆分與已知股息事件。
3. 以原型當日收盤更新歷史高點與回撤。
4. 若創新高，重置所有門檻的本週期觸發旗標。
5. 若未創新高，找出所有尚未觸發且已達成的門檻。
6. 訊號排入下一交易日開盤。
7. 成交日依門檻由淺至深執行；每層比例都是「該筆成交前可用現金」的百分比。
8. 同一週期同一門檻只執行一次；價格持續低於 -20% 不會每月重複買。
9. 沒有觸發時，新的每月投入持續留在資金庫。
10. 創新高後不賣出；當時全部現金自然成為下一週期的 100%。

例：同一天首次跨過 -20% 與 -30%，設定為 25% 與 40%，開盤前有 100 萬：

- -20% 層先投入 25 萬，剩 75 萬。
- -30% 層再投入剩餘現金的 40%，即 30 萬。
- 最後保留 45 萬。

### 9.3 股息

- **留在現金庫**：股息扣除可配置稅費後加入現金，可供未來門檻使用。
- **立即投入**：股息在可觀測事件後下一交易日開盤買入同一持有標的。

兩者皆使用實際股數計算，不以調整收盤再補一次股息。

### 9.4 策略結果

- 期末資產、持股市值、現金與累計投入。
- Money-weighted XIRR、time-weighted return。
- 與每月定期定額、全程持有現金、固定簡單門檻及買入持有基準比較。
- 最大回撤、ES5%、最長水下期、現金最低點。
- 每次買進日期、門檻、原型跌幅、ETF 跌幅、成交價、股數、投入額與成交後現金。
- 回撤週期使用率、未觸發現金、過早耗盡比例與最深層無資金可買的次數。

## 10. 最佳比例搜尋

### 10.1 搜尋空間

預設門檻為 -20%、-30%、-40%、-50%。每層比例候選為 0% 至 100%，以 10 個百分點為步進：

- 預設要求越深的門檻比例不小於較淺門檻，降低無意義組合與過度擬合。
- 進階模式可解除單調限制、改變步進、門檻數與範圍。
- 所有組合、排除規則與隨機種子保存於結果。

### 10.2 驗證

- 時間資料只能按時間切分，不隨機打散。
- 預設採多個 expanding-window／walk-forward 切片。
- 若獨立事件數不足以支撐切片，系統不產生「最佳」標籤，只顯示探索結果與樣本不足。
- 實際槓桿 ETF 與合成歷史分別評分；合成資料只能當壓力測試，不能替代實際樣本外績效。
- 鄰近參數表現一起檢查；只在尖峰勝出的組合降權。

### 10.3 三種輸出

- **保守**：優先保留深跌現金、降低 ES5%、現金耗盡與長期套牢。
- **平衡**：先限制最差 5% 結果、過早耗盡與長期套牢，再最大化樣本外 XIRR。
- **積極**：容許較低現金保留，以較高樣本外報酬與較快投入為主，但仍受集中度與壓力測試限制。

每個候選顯示：

- 參數、樣本內與樣本外結果。
- 相對基準改善。
- 風險約束是否通過。
- 鄰近參數穩定度。
- Pareto 前緣位置。
- 每個歷史切片的成敗，而非只有總平均。

「最佳」一詞只用於指定資料、參數與目標函數下的候選，不暗示未來最優。

## 11. AI 快速操控模式

專屬路徑 `/ai` 不要求 API key，提供：

- 可讀的標的、日期、門檻、比例、投入、股息與目標函數欄位。
- 所有控制項有穩定 `id`、`name`、`aria-label` 與 `data-ai-field`。
- 一鍵執行預設單調限制後的 1,001 個四層組合；解除限制時完整搜尋 14,641 個組合。
- 工作進度、可取消、錯誤碼與可重試狀態。
- JSON 匯入／匯出，使用和 OpenAPI 相同 schema。
- 結果表可依樣本外 XIRR、ES5%、現金保留、修復時間與穩定度排序。
- 「複製 AI 操作說明」產生逐步瀏覽器操作手冊與目前參數摘要。

另提供本機 CLI：

```powershell
.\scripts\Analyze.ps1 -Config .\examples\balanced.json
```

CLI 與網頁都呼叫同一 API，不另寫一套量化邏輯。

## 13. 報告

## 14. 錯誤處理

- **資料過期**：仍可開啟最後有效快取，但頂部固定顯示過期日期；正式報告預設禁止，除非使用者明確接受並留下註記。
- **資料缺口**：不跨缺口插值後假裝有交易；受影響區間從正式事件分析排除。
- **供應端失敗**：保留舊快取，顯示代碼、重試時間與可操作修復方式。
- **樣本不足**：不顯示誤導性的百分比精度，不產生最佳策略標章。
- **長工作**：持久化進度與階段；取消只在一致性檢查點生效。
- **計算錯誤**：工作標記失敗並保留可重現輸入，不寫入半份正式結果。
- **版本不相容**：schema migration 前備份 SQLite；無法遷移時唯讀開啟並提供復原指令。
- **Funnel 已占用**：不得靜默覆蓋其他本機服務。

## 18. 測試策略

### 18.1 量化單元測試

固定小型資料夾具驗證：

- 上月月底與非交易日截止。
- 價格回撤及歷史高點重置。
- 每日樣本和獨立事件計數不同。
- 起始日已在深跌區的多門檻觸發。
- 跳空跨越多層、同層單週期只觸發一次。
- 收盤訊號只能次日開盤成交。
- 新高重置但不賣出。
- 每月投入、年度增加、獎金、暫停與 ACT/365 利息。
- 股息留現金／再投入且不重複計算。
- 拆分後股數和市值守恆。
- 比例依每筆成交前剩餘現金計算。
- 實際與合成結果不可混入同一實績統計。
- XIRR、總報酬、MAE、MFE、ES5% 與修復時間。
- 優化器固定輸入與種子時完全決定性。

重要守恆條件再以 property-based tests 檢查，例如現金與股數不可無原因為負、零費用下交易前後總資產只受市場與外部現金流影響。

### 18.2 整合與契約

- 使用版本固定的本機市場資料 fixture，不讓 CI 依賴 Yahoo。
- provider 更新採 fake server 驗證增量、重試、原子替換與舊快取保留。
- API schema 與前端型別由 OpenAPI 對齊。
- SQLite migration 做升級、降級備份與損壞復原測試。

### 18.3 前端與端對端

- Vitest／Testing Library 驗證證據句、參數表單、警告與 AI 欄位。
- Playwright 驗證標的選擇、事件檢視、策略執行、報告匯出與 AI JSON 流程。
- 首要桌機尺寸 `1440×900`，手機尺寸 `412×915`，另驗證 `405×720`。
- 截圖檢查回撤帶、標記、圖例、焦點與手機抽屜。
- 無障礙掃描與鍵盤全流程。

## 19. 驗收條件

第一個穩定版本只有在下列條件全部成立時完成：

1. 所有指定標的可由設定表載入，台灣掛牌美股 ETF 不出現在清單。
2. 8 月啟動時政策截止顯示 7 月 31 日；資料已足夠時不發 Yahoo 請求。
3. -20%、-30% 等門檻同時顯示 `N_day` 與 `N_episode`，兩者不混稱。
4. 任意歷史日期都能成為策略起點，且訊號成交沒有前視。
5. 槓桿分析可清楚切換原型、合成與實際資料。
6. 現金庫正確處理可變投入、未用現金、新高重置、股息與永不賣出。
7. AI 模式無 API key 即可批次分析並輸出三種可解釋候選。
8. 圖表至少具備同步 pane、回撤帶、十字線、兩點量測、操作標記及盈虧資訊。
9. 全部 CI 檢查通過，正式計算不依賴網路測試。
10. 本機一鍵啟動、更新、備份、停止可用；Funnel 不會靜默蓋掉既有服務。
11. GitHub Pages 在本機關機後仍顯示基本介面與已發布匿名報告。
12. 維護文件能讓使用者完成部署、備份、回復版本與資料更新。
